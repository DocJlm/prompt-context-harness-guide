# 贡献指南

非常欢迎一切形式的贡献！

## 哪些贡献最受欢迎

| 优先级 | 类型 | 说明 |
| :---: | :--- | :--- |
| 🔥🔥🔥 | **错别字 / 链接失效修复** | 直接 PR 即可 |
| 🔥🔥🔥 | **真实案例补充** | "我用 helixent / deer-flow 做了什么"，分享给读者 |
| 🔥🔥 | **新的开源项目案例** | 比 helixent / deer-flow 更新的项目 |
| 🔥🔥 | **代码 Lab 增强** | 让 demo 更完整、更教学化 |
| 🔥 | **翻译** | 英文 / 繁体中文 / 日韩 |
| 🔥 | **新章节 / 新主题** | 见 [路线图](./roadmap.md) |

## 写作规范

- **中文为主，必要时英文**：核心论述用中文；术语首次出现保留英文原词。
- **每章 ≤ 6 个 `##` 标题**：太多会失去节奏。
- **用表格 / 代码块 / 引用**：减少长段散文。
- **每个论点至少有一个例子**：纯抽象的理论不收。
- **链接到一手资料**：博客 / 论文 / GitHub repo。

## 代码规范

- **Python**：`black` + `ruff` 默认配置。
- **依赖最小**：能用 stdlib 不用第三方；能用 1 个包不用 5 个。
- **demo 可运行**：每个 demo 必须**能在不到 1 分钟**跑出有意义结果。
- **OpenAI-Compatible 优先**：API 调用要兼容 `OPENAI_API_KEY` + `OPENAI_BASE_URL`，让国产模型也能跑。

## PR 流程

1. Fork 本仓库
2. 创建分支：`feat/<short-desc>` 或 `fix/<short-desc>`
3. 提交 → PR
4. CI 通过 + 至少 1 个 reviewer approve 后合并

## Issue 模板

提 issue 时请说明：

```
## 类型
- [ ] 错别字 / 链接失效
- [ ] 内容补充
- [ ] 新章节建议
- [ ] 代码 bug
- [ ] 其他

## 描述
...

## 涉及文件 / 章节
docs/zh-cn/02-context-engineering/01-context-anatomy.md
```

## 鸣谢

所有贡献者会出现在 README 底部。也欢迎在你的博客 / 公众号引用本教程（注明出处即可）。
